目前引擎：未切換

⚠️ 要有反應必須跟足呢個次序： (0) 撳「中文 (iFlytek)」或「英文 (Nuance)」——會即刻重新綁定 speech service, 等 speech_ready event 返嚟 (見上面「🔀 ASR 引擎已切換去」log) 先算完成; (1) 撳「開始聆聽」——呢個淨係將 speech engine 撥入接收 wake word 嘅狀態, 唔係即刻開始錄音; (2) 對住機械人講 wake word（實測確認：機身 config 寫死 CN_WAKEUP_NIHAO_ALPHA = 「你好，Alpha」，唔可以自訂/唔可以跳過）觸發硬件 mic array 偵測——呢個 wake word 偵測本身一直用緊 iFlytek 嘅硬件 CAE 引擎，唔受呢度揀 Nuance/iFlytek 影響; (3) 偵測到之後先真正開始錄音辨識, 呢陣先可以講指令。
⚠️ 2026-08 logcat 覆核發現（推翻上面舊結論）： 機身韌體自己 (AlphaMainSeviceImpl) 開機時已經自己 bind 咗一份獨立嘅 speech service, wake word 偵測 + TTS 提示全部行呢條獨立路徑，完全唔受呢度 「切引擎」呢個 app 側 API 影響——即係話呢個掣淨係改緊你自己個 app 主動 call `speech/tts` 或者 `speech/start_asr` 果條路徑，唔會令你聽到嘅 wake word 回答變聲、變語言。想改開機 wake word 用邊種語言，要用下面「⚙️ 機身語言設定」 個 preset (需要重開機)。
⚠️ Confidence 門檻（反編譯 Alpha2Services-v1.1.7.3.20 證實）： 自由辨識（wake word 之後嗰段，唔係下面嘅語法式辨識）由頭到尾都行 Nuance （NuanceASRImpl）。 Local recognition confidence 要 ≥4500 先會直接接受；低於此分數會嘗試等雲端補完， 但 Nuance 雲端伺服器已停用，所以低分結果實際上會全部失敗。企近部機、慢慢講、 咬字清楚可以提高 confidence。已確認用英文完整短句得（例如 "wave the left hand"， 唔好淨講單字），見下面已知指令參考。

機身有兩個 speech engine：Nuance VoCon（offline，內建喺 alpha2services）同 iFlytek。經反編譯 Alpha2Services-v1.1.7.3.20 證實：Nuance 呢邊 speech_initGrammar／startSpeechGrammar 係完全未實作嘅空 stub（method body 得一句 return-void），自訂詞彙一律唔會生效； 但呢邊有一個獨立、寫死喺 native code 嘅內建 grammar（下面呢個表），單靠 local recognition 就會 work，唔使雲端（Nuance 雲端伺服器已停用，但呢個內建 grammar 唔靠佢）。 單字容易 mis-parse（例如淨係講"wave"可能會 match 錯做 QA），建議用完整短句 （例如「wave your left hand」）。

⚠️ Confidence 門檻：反編譯證實 local recognition 嘅 confidence 分數要 ≥4500 先會直接接受（唔使等雲端）；低於呢個門檻會判 invalid、等雲端補完——但雲端已停用， 所以低於 4500 分嘅結果實際上會全部有去無回。想提高成功率：企近部機、慢慢講、 咬字清楚、減少背景噪音，呢啲都會直接影響 confidence 分數。

  • 模擬講嘢（onSpeech dictation，未測試，SDK標咗 @Deprecated 但搵唔到原因）—— 如果work，結果會經返「ASR」card嘅「辨識結果」／「意圖分類」顯示（同真正講嘢一樣嘅path）
  • 語法式辨識（initSpeechGrammar → startSpeechGrammar）—— ⚠️ 已反編譯確認：Nuance binding 之下係空 stub，一定失敗；要撞到 iFlytek 嘅真身實作（com.iflytek.cloud.SpeechRecognizer），要自己先用上面 「中文 (iFlytek)」掣切換，未切嘅話呢個測試會直接回傳 backend 個 guard error。 strGrammar 確實語法格式仍未反查完整，會將你打嘅嘢原封不動送去
